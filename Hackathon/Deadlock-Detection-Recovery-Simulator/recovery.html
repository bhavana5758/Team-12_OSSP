RECOVERY LAB / 03

Break the deadlock.

Detection identifies the blocked set. Recovery changes the resource state so that one or more processes can proceed.

01

Process termination

Abort one or more processes involved in the deadlock. Their allocated resources are returned to the available pool in the simulation.

DEMONSTRATED IN SIMULATOR
02

Resource preemption

Reclaim resources from a process and assign them elsewhere, when the operating system and resource type permit safe preemption.

CONCEPTUAL
03

Rollback

Restore a process to a previously saved state and restart it later. This requires checkpointing and application support.

CONCEPTUAL

Recovery decision checklist

Confirm the deadlocked set

Use the detector's unfinished process list; do not terminate unrelated processes without a reason.

Select a victim carefully

Consider priority, work already completed, resources held, and restart cost.

Release resources in the model

When a process is terminated, return its allocation to the available vector.

Run detection again

Verify that the deadlock is resolved or determine whether another recovery action is needed.

The website simulates process termination and resource release. It does not terminate real system processes or preempt real hardware resources.
