CONCEPTS / 04

Deadlock theory

The operating-system concepts behind the simulator: necessary conditions, resource state, and the detection procedure.

Four Coffman conditions

Mutual exclusion

At least one resource is non-shareable.

Hold and wait

A process holds resources while requesting additional resources.

No preemption

Resources are released voluntarily rather than forcibly taken under normal rules.

Circular wait

A closed chain of processes exists, each waiting for a resource held by the next.

Detection

Use current allocation, outstanding requests, and available resources to find processes that cannot finish.

Recovery

Change the system state to break the dependency and permit progress.

Detection algorithm: Work / Finish

Initialize

Set Work = Available. Initialize Finish for each process; processes with zero allocation may be marked finished.

Find a candidate

Find an unfinished process i where Request[i] ≤ Work for every resource type.

Simulate completion

Set Work = Work + Allocation[i] and mark process i finished.

Repeat

Repeat the search until no additional process can finish.

Interpret

Processes remaining unfinished with unsatisfied requests are reported as deadlocked candidates under the supplied state.

Key data structures

StructureMeaning
AvailableNumber of currently free instances for each resource type.
AllocationInstances of each resource type currently held by each process.
RequestAdditional instances each process is currently waiting for.
WorkTemporary vector used by the detection algorithm.
FinishTracks whether a process can be treated as completed in the simulation.
This detection method is distinct from the Banker's algorithm, which is commonly used for avoidance by testing whether a prospective allocation leaves the system in a safe state.
